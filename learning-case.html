01 / THE CASE

Can the material cover the plan?

The example models three finished assemblies sharing six components across eight BOM lines. A planner needs a consolidated shortage list before deciding which stock records and supply commitments to investigate.

  1. Combine requirements: multiply each product’s planned demand by its quantity-per-component, then sum shared components across products.
  2. Calculate available stock: subtract reservations for other commitments outside this production plan from on-hand inventory.
  3. Identify exposure: calculate nonnegative component shortages and multiply them by the sample USD unit costs.
  4. Investigate: confirm stock accuracy, incoming supply timing, and production priorities before changing the plan.

Assumptions: one shared inventory snapshot, single-level example revision B, EA units, and USD. Scenario demand is rounded to whole units, with .5 rounded up. Reservations stay fixed across scenarios. This case does not calculate dated MRP, stock allocation, or maximum buildable production.

03 / CHECK THE MATH

Every total is traceable.

Required = Σ(product demand × BOM quantity per)
Available = on hand − reservations for other commitments
Shortage = max(required − available, 0)
Shortage value = Σ(component shortage × component unit cost)

Base scenario: C01

FG-A requires 2 brackets per unit and has demand of 40. FG-B requires 3 brackets per unit and has demand of 30.

Required = (40 × 2) + (30 × 3) = 170
Available = 100 − 10 = 90
Shortage = 170 − 90 = 80
Value = 80 × $12 = $960

Base scenario: C05

FG-B requires 1 control module per unit. With demand of 30, it needs 30 modules; 25 are on hand and 5 are reserved for other commitments.

Available = 25 − 5 = 20
Shortage = 30 − 20 = 10
Value = 10 × $50 = $500
Total = $960 + $500 = $1,460

04 / THE BUILD

Data, calculation, and evidence.

Python / Django API

Validates component and product references, duplicate BOM rows, numeric inputs, stock reservations, units, and the example revision. A read-only endpoint returns the consolidated component rows, product exposure, and KPI totals.

GET /api/kpis/?scenario=base
GET /api/kpis/?scenario=low
GET /api/kpis/?scenario=high

Unknown scenario names return a 400 response. The project uses a local development server; it has no ERP integration or production authentication.

Browser dashboard

Uses the same input JSON with a separate JavaScript calculation so the public demonstration works without a server. Python and JavaScript results are compared for every component, product, and KPI across all three offered scenarios.

Shared component requirements are aggregated before stock is compared, so available inventory is not multiplied by joining it to multiple BOM rows.

Verification completed

12 automated Python tests passed. They cover expected component results, all three API scenarios, invalid inputs, read-only endpoints, whole-unit rounding, and zero-demand exposure. Three cross-language scenario comparisons check the browser calculation against Python and the expected totals above.

06 / CASE-STUDY SUMMARY

How I explain this project.

“I designed this case study around a manufacturing planning question: can available components support the production plan? I combined BOM, demand, inventory, and cost data, aggregated shared parts, and built a shortage calculator with a local Python/Django API and a browser dashboard. I checked the results across three demand scenarios. In the base example, two components are short and their uncovered requirement is valued at $1,460. The result is a focused investigation list; the next step would be checking stock and incoming supply with the planning owners.”
